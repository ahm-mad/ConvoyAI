## 1. UI structure conventions actually used

- **Screens** (Vehicles/Drivers/Yards/Geofences/Trips/Incidents): `div.flex.flex-col.p-5.h-full.overflow-y-auto` → header (`h1 text-[15px] font-display` + count line) with "Add X" button (`text-xs … text-accent-cyan border border-line rounded-md`) → inline `NewXForm` card (`bg-surface-1 border border-line-soft rounded-md p-4`) → `StatusChips` → `DataToolbar` (actions slot holds "Select page", "Select all N", "Export CSV") → `BulkBar` → error banner with Retry → loading text → empty state ("No X match… Clear them") → rows (`SelectableRow` + a full-width row `<button>`) → `Pager`. Geofences is a two-column screen (list + events panel).
- **Rows** are hand-built buttons (`bg-surface-1 border border-line-soft rounded-md px-4 py-3 hover:bg-surface-2`), retired/sold vehicles rendered at `opacity-60`; status badges are `text-[10px] px-1.5 py-0.5 rounded capitalize` with `bg-<status>/10 text-<status>`.
- **Detail modals** are fixed-width cards: Vehicle `w-[640px]`, Trip `w-[600px]`, Yard editor `w-[900px]`, all `max-h-[85vh] flex flex-col overflow-hidden` with header (title, live "updated" pulse for vehicles), a tab strip (`border-b-2 border-accent-cyan` for the active tab, tab names lowercase strings capitalised via CSS) and a scrolling body `p-5`. Tab state is local (`initialTab` prop lets callers deep-link: Overview attention items open the Vehicle modal on `maintenance | compliance | tracker | vehicle history`, Driver modal on `compliance`).
- **Inline forms inside modals** (schedule/log/fuel forms) use raw `<input>/<select>` with `bg-surface-1 border border-line rounded px-2 py-1.5 text-xs`; `PagedRecords` gives each sub-list its own `useListState(storageKey,{pageSize:10})` (search, extra selects, From/To date inputs).
- **Analytics pages** use `AnalyticsShell` (max width 1760, `px-6 py-6`, gap-5) + `KpiTile` grid via `useKpiColumns` + `WidgetCard`s in a 12-col grid (`col-span-12 xl:col-span-N`) + `DataTable` in server mode (`perPage 15`) with status chips above. The **Overview builds its own header/scroller** (does not use `AnalyticsShell`, so it does not pass `compareMode`/`interval` controls to `FilterBar`).
- Realtime "live" badge: Vehicle modal shows "Live — updated HH:MM:SS" from `dataUpdatedAt` (its tooltip still says "every 15s" while the real safety poll is 120 s — stale copy).

## 2. Behaviours worth knowing

- `VehicleDetailModal` OverviewTab: driver assignment goes through `/drivers/:id/assign-vehicle` (`OptionSelect kind="drivers" params={{assigned:0}}`); stats `distance_km_7d/30d`, `avg/max_speed_kmh_7d` (null → "— not measured"); mini-map with `RecenterOnUpdate`; a static note says fuel isn't a sensor stat. Maintenance tab "Add Schedule" form only sends `service_type, interval_days, last_service_date` (km interval only via edit form); "Log Completed Service" sends `maintenance_schedule_id` so the backend resets the schedule's next-due; both call `invalidateFleetQueries`.
- Fuel tab: default unit follows the company volume unit; economy shown via `u.economy.from()` only when `economy.unit==='km/L'`.
- `TripDetailModal`: safety refetch every 120 s only while `in_progress`; `awaiting_completion` banner + "Confirm completion"; complete/cancel/start/delete as in the entities doc; timeline computes the current stage from actual timestamps (origin → yard stops sorted by `sequence` → destination), a yard counts completed only with evidence (departure/`departed`/`completed`/arrival once past), `actual_source` labels `geofence_auto→Sensor`, `manual→Manual`, `driver_reported→Driver`. **The operator sees "Start Trip" on planned trips** (the driver-only Start is a future note).
- `StopActions`: only when trip is `in_progress|completed`; time defaults to now WITH seconds (so it isn't before a just-recorded arrival); replacing an existing time requires a reason; first 422 `errors.reason[0]` shown.
- `FleetMap`: two position queries — overview (`limit=1`, no bbox: centres the map on the newest reporting vehicle + total count) and viewport (`bbox`, `limit 2000`, `keepPreviousData`, 120 s poll); yards/geofences via `useViewportList` (≤500); a truncation notice appears when any layer is capped; trail on marker click via `/fleet/devices/{id}/history`; trip route overlay from a select fed by an **unpaged `GET /trips`** (only the first page → only the first 20 trips can appear in the selector — latent scale issue). `VehicleMarker` colour = fresh (<15 min hardcoded) green vs grey; popup title prefers the assigned vehicle's name.
- `DeactivateControls`: inline two-step confirm; when `inactive` shows a Reactivate banner (+ optional `PermanentDeleteControl`); toast uses `response.message`. `RecordItem`/`DeleteControl`: inline confirm, refetch via `invalidateFleetQueries`.
- `RecordForm`: initial values snapshot → only changed keys sent; `qty:'distance'` fields (label "(km)" replaced with the unit label) converted; whole-number km fields rounded; select options that look numeric are sent as numbers; "nothing to save" toast if unchanged; 409 handled through `useEditConflict`.
- `DataTable` (analytics): sort cycle desc → asc → none; server search debounced 300 ms; skeleton rows while loading; `aria-sort`, `caption` sr-only, `tabular-nums`; client CSV builds UTF-8 BOM blob (server mode uses the export endpoint).
- `useAnalyticsFilters`: URL is the state (`router.replace(..., {scroll:false})`); presets today/7d/30d/mtd/custom; default 7d; compare default ON; year shown in labels when the range is not within the current year.

## 3. Deviations from the owner's own rules found in the Fleet code (candidates for the UI pass / fixes — all need owner approval before changing)

1. **Hardcoded map fallback centre = Lahore** `[31.4757729, 74.3399971]` in `FleetMap.tsx`, `TripRouteMap.tsx`, `CoordinatePicker.tsx` (violates "no hardcoded city").
2. **Hardcoded hex colours** outside the tokens: map layers (`TripRouteLayers` 13, `VehicleMarker` 5 incl. freshness colours `#17d68c/#565f68`, `YardMarker`, `TripRouteMap`, `FleetMap` geofence circle `#f5a623` and trail `#29d3ff`, `CoordinatePicker`), plus a few in `FleetSettings`, `KpiTile`, `FilterBar`, `Worklist`, `ComplianceView`, `YardLayoutEditor`. Leaflet markers are HTML strings so they can't use CSS vars directly.
3. **Marker freshness is hardcoded to 15 min** (`VehicleMarker.isFresh`) instead of the company `position_freshness_minutes` used by the dashboards.
4. **Raw HTML controls** in Fleet: `<select>` in 11 files, `type="date"` ×13, `datetime-local` ×5, raw `<input type=checkbox>` — the global UI pass is meant to replace these.
5. Static unit strings inside some `FieldDef`/`NumDef` (`'Interval (km)'`, `unit:'km'`) rely on later label replacement; verify any new field with a `qty`.
6. **No i18n** in Fleet (all English literals). No route/permission granularity (all-or-nothing `all-fleet`).
7. Sort/paging state of list screens lives in sessionStorage per tab, not the URL; analytics pages keep the URL as state.
8. `FleetMap` trips selector unpaged (see §2); Vehicle modal tab-strip copy "Refreshes automatically every 15s" is outdated.
9. Several fleet files are still `@ts-nocheck` (VehicleDetailModal, TripDetailModal, FleetDashboard) — API entities are `any` everywhere.

## 4. Extension points (where new Fleet features plug in)

- **New list screen**: copy the recipe in `fleet.md` §3 (`useListState` + `useServerList` + toolbar/chips/bulk/export) and give the query a fleet-prefixed name so realtime refetches it.
- **New record type in a modal**: add a `FieldDef[]` in `records/fields.ts`, wrap items in `RecordItem`, page them with `PagedRecords` (query name starts `vehicle…`/`driver…`).
- **New analytics page**: a hook in `src/hooks` (`fleet-dashboard-an-*` key, `keepPreviousData`, `refetchInterval` 300000, export params), a screen using `AnalyticsShell` + `useAnalyticsFilters` (+ `useAnalyticsScope(fields)` only if EVERY widget honours it), add to `FleetNav` `ANALYTICS` (+ `SCOPE_CARRY`), route file under `app/(app)/fleet-management/analytics/<name>/page.tsx`.
- **New realtime rule**: add a `subscribeFleetEvent` handler in `useFleetRealtime` using `scheduleInvalidate` (never invalidate per event).
- **Per-company setting**: add to `FleetSettings` (`NumDef`) + `useFleetSettings` type; anything measured in km/L/m/kg must go through `utils/units.ts`.
