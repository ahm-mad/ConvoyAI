# Map kit (T-006) — `src/components/map/`

One MapLibre GL map for the whole product. Nothing outside this folder imports `maplibre-gl`; screens compose layers as children of `<ConvoyMap>`.

- `ConvoyMap.tsx` — the map: `look` (light | night | satellite), `mode` (2d | 3d), `center` [lat, lon], `zoom`, `onBoundsChange(bbox)` (debounced, padded, same `[w,s,e,n]` shape the API `bbox` param uses), `onReady(map)`, `scrollZoom`, `interactive`. Context: `useConvoyMap()` → `{ map, styleVersion, look, mode }`; layers re-add sources when `styleVersion` changes (a look switch replaces the style). Worker file is served from `/public/maplibre` (postinstall copies it).
- `mapStyles.ts` — MapTiler `streets-v2` re-painted from `--map-light-*` / `--map-night-*` tokens (tokens.css); `hybrid` for satellite. Latin labels first.
- `useMapPrefs.ts` — persisted `{ look, mode, iconStyle }` (localStorage `convoyai-map-prefs`), shared by every map.
- `MapToolbar.tsx` — look / 3D / fit / icon-style controls (+ children slot for screen tools: demo speed, follow, tour, clean, fullscreen). `MapHud.tsx` — live count chips.
- `layers/`: `VehicleLayer` (HTML markers, gliding tween + bounded dead reckoning, zoom scaling, clusters below z8.5, comet trails, selection card, follow), `RouteLayer` (trip road path + glow + beacons), `HistoryLayer` (recorded trail), `YardLayer` (pads), `GeofenceLayer` (zones), `PinLayer` (draggable pin + radius), `Scenery3D` (terrain, hillshade, sky).
- `vehicle/` — `vehicleKinds.ts` (category → kind, motion state, `LiveVehicle`, `vehicleFromPosition`), `VehicleIcon.tsx` (silhouette | badge | puck; CSS `.cv-veh*` in components.css uses state variables, no hex).
- `qaRaf.ts` — QA-only requestAnimationFrame pump for the hidden automated tab (`localStorage['convoyai-qa-raf']='1'`); dev-only `window.__cvMap`, `__cvSim()`, `__cvGlVehicles`.
- Showcase: `src/utils/showcase/{routes,simulation}.ts` — real OSRM road geometry (generated once by `scripts/build-showcase-routes.mjs`) and a wall-clock-driven fleet simulation (`demo speed` ×1…×60 via `convoyai-demo-speed`); the map polls every 700 ms in showcase.

Adding a map screen: `const ConvoyMap = dynamic(() => import('@components/map/ConvoyMap'), { ssr: false })`, pass `look/mode` from `useMapPrefs()`, add layers as children. Give the map a parent with a real height.

**Gotcha, found 2026-10-03 (real crash, not theoretical):** every layer effect keyed on `styleVersion` that calls `map.addSource`/`map.addLayer` must wrap the call in try/catch with a one-time `map.once('idle', ...)` retry. MapLibre throws `"Style is not done loading"` if `addSource`/`addLayer` runs while a `look` switch's internal `setStyle()` is still resolving, even though the `style.load` event (which bumps `styleVersion`) has already fired. Pattern (see `RouteLayer.tsx`, `GeofenceLayer.tsx`, `HeatLayer.tsx`, `HistoryLayer.tsx`, `PinLayer.tsx`, `MissionRouteLayer.tsx`, `RouteContextLayer.tsx` for the exact shape): extract the add-source/add-layer block into a named function, call it in `try {}`, and on catch retry once via `map.once('idle', () => { try { ... } catch {} })` — a bare catch-and-drop would silently leave the layer missing instead of crashing, which is just as wrong. This was an uncaught-exception crash (Next.js error screen, whole app down) triggered by switching Light/Dark/Satellite while a route or geofence/trail layer was actively rendering — easy to miss in normal QA since it only reproduces when a style toggle is exercised while something else is on screen.

## Map gotchas learned in the deep audit (2026-09-28/29)

- `map.panBy([dx, dy])` moves the CENTRE: to move content down by n px use `[0, -n]` (a sign slip once panned the vehicle out of view). The selected-vehicle card auto-pans into view (top clearance 84 px ≥ lg, 132 px below; toolbar + HUD).
- A vehicle that leaves the viewport list (bbox refetch) drops its selection; flights therefore select only after `moveend` (search, saved views).
- Changing the toolbar 3D state starts its own `easeTo` and cancels a `flyTo`: apply it AFTER the flight (`MapViews`).
- Dash-pattern animation costs CPU but the owner prefers smoothness (rule: UI beats efficiency) — do not "optimise" the route flow.
- Attribution/AbortError noise from cancelled tile fetches is filtered in `ConvoyMap` (unhandledrejection).
- Satellite labels are forced Latin (`mapStyles.latinLabels`).
- Fullscreen: modals render outside the fullscreen element, so the screen exits fullscreen before opening one; a refused `requestFullscreen` is swallowed (verified only in a focused, foreground window).
- Embedded maps (vehicle/trip modal) take `zoomControls`; `/map` has the toolbar without the icon-style group (`showIconStyle={false}`).
- `qaRaf.ts` (QA only, `localStorage convoyai-qa-raf=1`): ticks from a Worker with backpressure (ack before the next tick). Its earlier MessageChannel spin burned a full core; the first Worker version without backpressure froze the tab — never post ticks unconditionally.

## Map realism (2026-09-27, T-006-R item #0)

- `VehicleLayer` motion = buffered interpolation: markers are drawn ~1.15 fix-gaps in the past and move linearly between the last two REAL fixes (heading from the movement, eased); dead reckoning stays only for feeds slower than 2.5 s per fix. Markers use `subpixelPositioning: true` (MapLibre otherwise rounds to whole pixels → 1 px stair-steps at slow speed).
- Cluster bubbles are `ClusterItem`s keyed by lowest member id, glide toward the group centre (0.35 s), hold still while hovered, hover = halo only (no scale).
- `layers/MissionRouteLayer.tsx` (+ `simulation.missionRoute(vehicleId)`, showcase only): selected vehicle's road, bright ahead / dim behind, hover = lighter preview via `VehicleLayer onHover`. Trip beacons/ETA still come from `RouteLayer` (dropdown).
- Showcase sim: default demo speed ×3 (`DEFAULT_DEMO_SPEED`, storage key `convoyai-demo-speed-v2`), trapezoid accel/brake + end dwell for trips, real stops for loop vehicles. Landing hero keeps its own ×30 time-lapse (country zoom).

## Two real bugs found building the landing scroll story (2026-09-27)

- **`ConvoyMap` never called `map.resize()`.** Fixed: it now keeps a `ResizeObserver` on its own container for the map's whole life (added right after map creation in `ConvoyMap.tsx`). Without it, a map that mounts before its container's final size is established — a `sticky` panel settling into place, a lazily-mounted map — paints at the right CSS size but keeps a stale internal transform, so every marker projects to the wrong pixel (looked like the map thought its container was ~10× too big). This fix benefits every map on the page, not just the one that exposed it.
- **Raw `map.easeTo`/`flyTo`/`jumpTo` calls need `[lon, lat]`; the `<ConvoyMap center>` PROP takes `[lat, lon]` and converts it internally.** Reusing the same tuple for both (as the landing scroll story first did for its fallback camera) silently puts the camera somewhere else entirely — the numbers stay "valid" coordinates, so nothing throws. `FleetMap.tsx`'s `pickVehicle`/`pickYard` already had this right (`[v.lon, v.lat]`); any new direct `map.*To(...)` call must match that, not the `ConvoyMap` prop's order.

## 3D vehicle models (2026-10-02, T-006 item 2 — the last map-polish step)

Real glTF vehicle models (deck.gl `ScenegraphLayer`, interleaved with MapLibre) for the tilted-3D close-up look, replacing the flat `VehicleIcon` silhouette for individual (non-clustered) vehicles while the map is in 3D mode. Flat icons stay exactly as before everywhere else (2D mode, clustered, zoomed out) — see `agent/work/decisions.md` 2026-10-02 for the full options-discussion/decision record.

- **Code**: `src/components/map/vehicle3d/{models.ts,Vehicle3DOverlay.ts}` + the integration inside `VehicleLayer.tsx` (search `vehicle3D`/`show3D`). `Vehicle3DOverlay` is a plain class (not a React component) so it can be driven straight from `VehicleLayer`'s existing per-frame `requestAnimationFrame` loop instead of duplicating its interpolation/dead-reckoning logic.
- **Assets**: `public/models/vehicles/*.glb` — `sedan/van/truck/truck-flat` are Kenney's CC0 Car Kit (sourced, see that folder's `README.md`); `bus/semi/tanker` are procedurally generated (`scripts/generate-vehicle-models.mjs`, no CC0 bus/semi/tanker pack existed) in the same flat-shaded style. All 7 go through one `fix-vehicle-model-axes.mjs`/generator-baked `AXIS_FIX` rotation (+120° about the (1,1,1) diagonal) — **mandatory**, because every source file is authored +Y-up/+Z-forward like any normal glTF, while deck.gl's `ScenegraphLayer` Euler orientation treats +Z as up and +X as forward; skipping this on a new/re-downloaded model makes it render lying on its side.
- **LOD**: a vehicle only gets a 3D model when `mode==='3d'` AND it isn't folded into a cluster bubble (`e.el.style.display!=='none'`) — computed every frame in `VehicleLayer`'s existing loop, alongside the `.is-3d` class toggle (see below). Full fleet-wide 3D rendering was deliberately NOT done, to bound GPU cost.
- **Flat-icon handoff**: the flat DOM marker is NOT removed/hidden (`display`) when a 3D model takes over — only its drawn shape fades to `opacity:0` (`.is-3d .cv-veh__svg/__disc/__chev` in `components.css`), so the halo glow, the hit area, and every existing keyboard/click/hover/selection-card behaviour keep working completely unchanged on the same element. **Gotcha found building this**: `is-3d` is set on the MapLibre marker's OUTER wrapper div (`VehicleLayer`'s `e.el`); `.cv-veh` is on the INNER div React portals `<VehicleIcon>` into as its _child_ — `.cv-veh.is-3d` (same-element selector) silently never matches; it has to be the descendant-combinator form (`.is-3d .cv-veh__svg`) shown above.
- **Size floor**: `ScenegraphLayer`'s `sizeMinPixels: 18` (and a `sizeMaxPixels` cap) — without it a real-metre-scale truck is a handful of sub-pixels at country zoom and just vanishes, unlike the flat icon which has its own zoom-based floor (`VehicleLayer`'s `vs`).
- **A real bug found by the owner, fixed 2026-10-02: 3D models could look "bigger than a city" when zoomed out.** The `sizeMinPixels` floor above is a FIXED pixel size regardless of zoom; it's necessary for the model to be visible at any normal interactive zoom (at the zooms this was designed for, real-metre scale is itself sub-pixel), but at low zoom the map's own geographic context (roads, whole cities) shrinks much faster than a floor-clamped model does, so the two go badly out of proportion. This was reachable in practice because `clusterPass` deliberately never folds the **selected or followed** vehicle into a cluster bubble, even at country-level zoom — so selecting a vehicle and then zooming out left its 3D model alone on screen at a fixed ~18px+ size while the whole country shrank around it. Fixed with a dedicated zoom gate, `VEHICLE_3D_ZOOM = 13`, added to `show3DMode` in `VehicleLayer.tsx` (`modeRef.current === '3d' && map.getZoom() >= VEHICLE_3D_ZOOM`) — below that zoom, every vehicle (selected or not) uses the flat icon, whose own zoom-based scale (`vs`) already degrades gracefully. 13 was picked to match the zoom range the earlier live spot-checks (orientation testing, visual-quality pass) were actually done at and found to look proportionate; it is not deeply tuned beyond that, and the owner may want a different cutover point.
- **Two real deck.gl ↔ this maplibre-gl build (6.11.2) incompatibilities found and patched** (`patchMapForDeckGlCompat` in `Vehicle3DOverlay.ts`, full writeup in the code comment there): this maplibre-gl build exposes no public `map.transform` at all (confirmed by walking the whole prototype chain live — nothing there, despite the published `.d.ts` claiming a getter), which deck.gl's mapbox/maplibre interop reads in two places — `centerCameraOnTerrain` (`.elevation`, only when `map.getTerrain()` is truthy, i.e. the instant 3D mode's hillshade terrain is on) and `getViewport` (`.height`, read **unconditionally on every render frame**, not gated by terrain at all — this one meant the layer loaded its models successfully but never actually drew anything, with no thrown error reaching the app, only a per-frame warning from the qaRaf harness). Fixed by making `map.getTerrain()` always report "no terrain" to deck.gl specifically (nothing in this app's own code calls `getTerrain()` for any decision, only `setTerrain()` — so this doesn't touch the real hillshade rendering at all) and shimming a minimal `map.transform = { height }` getter from the map's own container height.
- **A React Strict Mode (dev-only) race, also found and fixed**: deck.gl's interleaved overlay starts an ASYNC WebGL device attach inside its constructor; React 18's dev-only double mount→cleanup→mount for every effect created two overlays back-to-back trying to attach to the map's one shared GL context, throwing "WebGL context already attached to device webgl-device-1". Fixed by deferring the actual `new Vehicle3DOverlay(map)` construction one `requestAnimationFrame` past the effect body and cancelling it in cleanup — StrictMode's synchronous double-invoke means only the surviving mount's rAF ever fires, so only one overlay is ever actually constructed.
- **A real heading bug, found via a deliberate pitch=0/bearing=0 top-down test and fixed**: `getOrientation` was written as `[0, 0, headingToYaw(d.heading)]` — but `ScenegraphLayer`'s orientation order is **`[pitch, yaw, roll]`**, so the heading-derived value was landing in the **roll** slot (rotation around the forward axis) instead of **yaw** (rotation around up), with yaw silently stuck at a constant 0 for every vehicle regardless of its real heading. At the normal tilted 3D camera (pitch 58°, any bearing) this read as merely "a bit off, maybe foreshortening," which is exactly why it survived initial live spot-checks — only an isolated `map.setPitch(0); map.setBearing(0)` test (removing all perspective ambiguity, comparing a vehicle's known `--h` heading against which screen direction its model pointed) made the 90°-ish-looking-wrong silhouette unambiguous. A fully independent, from-scratch check of the `AXIS_FIX` rotation itself (load the already-baked `sedan.glb`/`van.glb` in a plain Y-up three.js viewer, confirm the model is now lying on its side with its known hood/cargo-back end on the new +X/-X faces — which it was, correctly) had already ruled out the axis-fix step as the problem, which is what pointed at the orientation-array wiring instead. Fixed: `getOrientation: d => [0, headingToYaw(d.heading), 0]`. Re-verified with the same pitch=0/bearing=0 method on several vehicles/kinds (van heading ≈346° pointing correctly near-vertical/slightly-left, pickup/tanker/truck headings near south/northeast all pointing the matching screen direction) — correct now.
- **Verified live** (dev server, showcase data): models load (network 200s on first selection of each kind), no console errors/exceptions anywhere across all 8 `VehicleLayer` mount sites (Live Map, login's night map, the landing page's 3 maps, Overview hero, both 2D-only modal maps), 3D models render upright and correctly oriented (heading bug above now fixed and independently re-verified) for car/van/truck/pickup/tanker/semi, flat-icon halo + card selection still function. **NOT yet verified**: production build, axe.
