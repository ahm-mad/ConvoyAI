# FACTS — stable architecture facts both sides should know

Living reference, not a log — update a row in place when it changes (don't append a new one), and put a
short note in `communication/findings.md` if a change is significant enough to flag to the other side.

| Fact                  | Detail                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Realtime transport    | **Socket.IO**, not Pusher. One connection per logged-in user, JWT in `auth.token`, server puts the socket in room `user:{id}`. Full contract: `api_contract/API_CONTRACT.md` §4. Frontend implementation: `src/contexts/SocketContext.tsx`.                                                                                                                                              |
| Auth                  | `Authorization: Bearer <token>` (REST) / `auth: { token }` (Socket.IO handshake) — same JWT, from `POST /api/login`, valid 7 days.                                                                                                                                                                                                                                                       |
| Ingestion webhook     | `POST {API_ORIGIN}/api/webhook`, header `token: <per-product token from POST /api/get-encrypt-token>`. Body = raw ChirpStack-shaped uplink JSON (`deviceInfo.devEui`, `object.<attribute>`, …). MQTT ingestion path exists in the frontend UI (protocol tabs) but is **not implemented** end-to-end yet, per the owner (2026-09-22) — HTTPS is the only working connectivity type today. |
| Local dev origins     | Frontend `http://localhost:3000` (`npm run dev`, see this repo's `DEV_PERFORMANCE.md` if it's slow/crashing — frontend-internal). Backend `http://localhost:8080` (`NEXT_PUBLIC_API_URL` in the frontend's `.env.local`).                                                                                                                                                                |
| Real seeded test user | `junead@chaminade-hs.org` / `password123` (per the owner, 2026-09-22). **Do not use the demo account (`demoAccount@chirptech.io`) for integration testing** — demo mode is a client-only mock backend (MSW + Dexie, `src/utils/fakeBackend/`), unfinished/separate work; it never touches the real backend and proves nothing about real integration.                                    |
| Fleet realtime (company room) | The same JWT puts a socket in room `company:{id}` when it carries a company **and** the `all-fleet` permission. Events: `fleet:position`, `geofence:event`, `trip:update`, `fleet:changed { entity, id, action }` (actions incl. `checked_in` / `checked_out`), and `fleet:status_summary { total, moving, idle, parked, offline, no_tracker }` (only when the counts change; no heartbeat). All best-effort — keep refetch-on-reconnect / focus. Contract: `api_contract/API_CONTRACT.md` §4 / §4.6. |
| Company fleet settings + timezone | `GET/PUT /fleet/settings` (timezone, position freshness — default 15 min, idle threshold, scheduled hours per vehicle per day — default 24, on-time grace, maintenance due-soon window, KPI targets). **Until a company saves settings everything runs on the defaults, and the timezone is UTC.** Dashboard / analytics `from` / `to` are calendar dates (`YYYY-MM-DD`) in the company timezone; day / week / month buckets start at local midnight (weeks on Monday); `meta.timezone` says which zone was used. |
| Fleet list / table conventions | Server-side lists: optional `page` / `per_page` → `data: { items, pagination }` (absent = the flat array), except the lists documented as **always paged** (sub-lists, `GET /incidents`, `GET /maintenance-schedules`, `GET /fleet/attention`); `search`, `sort_by` / `sort_order` (NULLs last), filters; id lists as `a,b` **or** `a[]=…&a[]=…`; streamed CSV `…/export`; bulk actions by `ids` or `filter` (≤ 500, per-record results); optional `expected_updated_at` → 409 on the fleet `PUT`s; audit fields `created_by` / `updated_by` (+ `_user`) on fleet records. |
| Analytics definitions (fleet) | Trips belong to the period of `actual_start_at`, else `planned_start_at`; one distance = completed trips' `actual_distance_km` (+ `distance_source`); fuel = fuel-log litres, economy = full-tank method (`null` when there is no interval); status = exclusive `moving / idle / parked / offline / no_tracker`; utilisation = completed-trip hours ÷ in-service vehicles × scheduled hours × local days. Every metric of the analytics endpoints carries its basis in `x-quirks` / `meta.data_quality`; `meta.definition_version` bumps when a formula changes. |
| Never break what works | Owner rule (2026-09-25), both sides: nothing already working may be broken, project-wide; anything that must change → ask the owner first, then inform the other side (flow file "Changes to EXISTING behaviour" checklist + a `STATUS.md` paragraph); prefer additive changes; re-test the unchanged flows. See `README.md`. |
| Yard occupancy + geofence activity (fleet) | `GET /fleet/analytics/yards`: occupancy = open yard stays **now** ÷ slots (point-in-time — no history, does not follow `from` / `to`), dwell = check-out − check-in over stays checked out in the period, `null` when nothing to measure. `GET /geofences/events/summary`: counts exactly the events `GET /geofences/events` shows (a geofence's CURRENT `alert_on` of `enter` / `exit` hides the other type), buckets in the company timezone (`hour` labels `YYYY-MM-DDTHH:00`, ≤ 168 buckets). Both default to the last 7 local days. |
| Fleet record lists + compliance counts | `GET /maintenance-logs`, `GET /fuel-logs` (+ `/export`): company-wide, always paged, item = the per-vehicle log + `vehicle` brief; logs of retired / sold vehicles included; `meta.summary` covers the whole filtered set (fuel litres convert gallons; cost = `total_cost` else `cost`; price per litre over the priced fills only). `GET /compliance-documents/counts`: six exclusive buckets (`expired`, `expiring_0_7`, `expiring_8_30`, `expiring_31_60`, `valid_after_60`, `no_expiry`) against today in the company timezone. `GET /compliance-documents/expiring-soon?within_days=N` (default 30). |
| Bucket caps (fleet analytics) | The analytics endpoints (`/fleet/analytics/summary`, `/fleet/analytics/yards`, `/geofences/events/summary`) refuse more than **92** buckets (hour interval: **168**) with a 422 that names the fix. The older `GET /fleet/dashboard/trends` (Laravel-parity, unchanged) has **no cap**: every bucket runs several queries one after the other, so `interval=day` over years is slow — use `week` / `month` for long ranges. |
| Trips report (fleet) | `GET /fleet/analytics/trips`: same definitions as the dashboard (period = actual start else planned start; on-time only over completed trips with a planned and an actual end, `null` when none; distances as the dashboard). **`driver_id` on this endpoint = the trip's OWN driver; on `/fleet/analytics/summary`, `/fleet/status-summary` and the performance table `driver_id` = the vehicle's CURRENT driver.** `status` narrows the table only. Retired / sold vehicles' trips are included. `delay_minutes` is signed (negative = early), `null` when the trip cannot be judged. |
| Fuel report (fleet) | `GET /fleet/analytics/fuel`: the dashboard's fuel definitions (local `fill_date`, gallons → litres, cost = `total_cost` else `cost`, price per litre over the priced fills only, full-tank economy from the range's fills, fuel cost per km over the completed trips' km). Economy intervals sit in the bucket of the fill that closed them. Anomaly flags (heuristics, not verdicts): `over_capacity` (vs the vehicle's current tank capacity), `economy_drop` (vs the vehicle's other intervals, `economy_drop_pct` default 30 — a request parameter), `odometer_backwards`. Table filters never change the summary; retired / sold vehicles' fills are included; no `driver_id`. |
| Maintenance + compliance reports (fleet) | `GET /fleet/analytics/maintenance`: costs by the local `service_date` (retired / sold vehicles included), cost per km over the completed trips' km, schedule buckets **point-in-time** for the vehicles in service (same states as `GET /maintenance-schedules`). **Downtime days do not exist — no vehicle status history.** `GET /fleet/analytics/compliance`: **point-in-time**, documents + the licences of the drivers that are not deactivated, six expiry classes (the C4 classes) against today in the company timezone, `compliance_rate_pct` = not expired ÷ records having an expiry date (no-expiry records not judged). |
| Unit system (fleet) | `GET/PUT /fleet/settings` carries `unit_system` = `metric` (default) \| `us` \| `uk` — a **display preference only**: the API stores and returns METRIC everywhere (km, litres, metres, kg, km/h, the `_km` / `liters` CSV columns), the client converts for display and converts typed input back to metric before sending. Optional on `PUT`, invalid → 422 `The selected unit system is invalid.`; per company (no per-user override). |
