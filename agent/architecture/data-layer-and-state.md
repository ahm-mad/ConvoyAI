# Data layer & state

## 1. HTTP: `axiosConfig.ts` + `src/utils/apiHelper.ts`

- `axiosConfig.ts` (repo root, alias `@root/axiosConfig`): one axios instance, `baseURL = NEXT_PUBLIC_API_URL` (**with trailing slash**; call sites use `/api/...` with leading slash — axios collapses it),
  request interceptor adds `Authorization: Bearer <localStorage.token>`; response interceptor has the 401 → `hardLogout()` **commented out** (do not re-enable without owner approval; it may interfere with demo mode).
- `apiHelper.ts` exports `get(url, params)`, `post(url, data, config, showToast=true)`, `put(...)`, `del(url, config, showToast=true)`. **They never throw**: errors are _returned_ as
  `{ error: true, message, status?, errors?, current? }` (`status` = HTTP status, `errors` = 422 field map, `current` = 409 details). `post/put/del` wrap the request in `toast.promise()` by default
  (generic "Processing…/Updating…/Deleting…" toasts) — **pass `false` as the last arg to suppress** (used almost everywhere in Fleet; forms show their own toast).
  Typical pattern: `const res = await post(url, payload, {}, false); if (res?.error || res?.success === false) { toast.error(res.message); return; } toast.success(...); onCreated?.(); onClose?.();`
- `src/types/api.ts`: `ApiResult<T=any>` is deliberately loose (`data`, `success`, `message`, `error`, + any key) — API response shapes are NOT typed (owner decision). Also hand-written `User`, `Role`, `Permission`, `Company`, `LoginResponse`, `LaravelPaginated`.
- Binary/CSV: `utils/serverExport.ts` `downloadServerCsv(path, params, fallbackName)` fetches `GET …/export` as a Blob with the axios client (bearer needed), reads `content-disposition` + `x-export-row-count`,
  turns a JSON 422 body (over the 50,000-row cap) into an Error. `utils/csvDevices.ts` = client CSV parsing/validation for device bulk import (≤500 rows, required columns `device_unique_identifier,name,location`).
- Uploads use `multipart/form-data` (`post(url, formData, {headers:{'Content-Type':'multipart/form-data'}}, false)`): floor plans, vehicle image, yard layout, profile picture, products (CSV + JSON).
- Images: `utils/avatar.ts` `resolveImageUrl()` (absolute/blob/data untouched; legacy relative → `<API>/storage/<path>`) and `getAvatarInitial()`.

## 2. react-query conventions

- `QueryClient` defaults: `retry:1`, `refetchOnWindowFocus:true` (no staleTime). `useSimpleQuery(key, url, params, options)` (`src/hooks/useSimpleQuery.ts`) → `useQuery({ queryKey:[key, params], queryFn:()=>get(url, params), networkMode:'always', ...options })`.
  **The query key is `[name, params]`** — realtime invalidation matches on the first element (a string). Pass `url=null` + `{enabled:false-ish}` for conditional queries (`null` url means the queryFn would call `get(null)` if `enabled` is not set — always pair with `enabled`).
- `usePaginatedQuery` (limit/offset style) exists but is **imported nowhere (dead)**. Legacy screens (`ManageProduct`, `RuleBuilder`, `ManageDevice`) keep their own `page/per_page/search/sort` state with `useSimpleQuery` (RuleBuilder debounces 1 s).
- **Refresh strategy**: mutations refetch their own list via `refetch()`/`onCreated` callbacks, NOT `invalidateQueries` — EXCEPT Fleet, which uses `invalidateFleetQueries(qc)` (`utils/fleetCache.ts`, predicate on the query-name prefix: `fleet-`, `trip`, `vehicle`, `geofence`, `yard`, `driver`, `assignable-trackers`).
  Fleet query names therefore MUST start with one of those prefixes to receive realtime refetches (e.g. `vehicles-paged`, `trips-list`, `fleet-dashboard-an-*`, `fleet-dashboard-ov-*`, `geofence-events`, `trip-{id}`, `trip-route-{id}`, `vehicle-detail-{id}`).
- Fleet lists use `placeholderData: keepPreviousData` (v5) so paging/filtering never flashes empty.

## 4. Realtime: Socket.IO (`contexts/SocketContext.tsx`)

One `io(apiOrigin, {path:'/socket.io', auth:{token}, transports:['websocket','polling']})` per user, created in `initializeSocket(userId)` from `Bootstrap` (demo users get a sentinel + a `window` `MSW_SOCKET_EVENT` CustomEvent bridge instead).
Each server event is bound **once** at module level and dispatched by id from tables:
`bindDashboardEvent(id,cb)`, `bindBuildingEvent(id,cb)`, `bindDeviceValueEvent(productId,cb)` (+ unbind), `bindAllInitialPacketEvents(products, cb)` (one consumer: `GlobalPacketListener` → persistent "packet received, configure" toast),
and fleet events with **multiple listeners per event** via `subscribeFleetEvent(name, cb) → unsubscribe`: `fleet:position`, `geofence:event`, `trip:update`, `fleet:changed`, `fleet:status_summary`, plus the local pseudo-event `fleet:connected` (raised on every (re)connect → refetch what was missed).
Not wired on the frontend: `alarm:state`, `notification:new` (see deferred list). Payload shapes: `backend/realtime-events.md`.
`useFleetRealtime()` (`hooks/useFleetRealtime.ts`, mounted once by the fleet layout / legacy hub): patches positions into cached queries in place, and **coalesces** invalidations (350 ms quiet, ≤1.5 s max) — a 500-record bulk action emits one event per record.
Rules: `trip:update` → `trips-list*`, `trips-counts*`, `fleet-map-trips`, `trip-{id}`, `trip-route-{id}`, `fleet-dashboard*`; `geofence:event` → `geofence-events`; `fleet:changed{entity}` → per-entity prefix sets (vehicle→vehicle/driver/fleet-positions/assignable-trackers, driver→driver/vehicle, yard→yard/geofence, yard_slot→yard, geofence→geofence);
`fleet:status_summary` → `fleet-dashboard-ov-status*` + `…-attention*`; `fleet:connected` (after first) → all fleet keys.

## 5. Hook catalog (`src/hooks`, all TS)

**Generic lists (Fleet enterprise foundation, flows/06):**

- `useListState(storageKey, defaults)` → `{state{page,pageSize(20),search,filters{},sortBy,sortDir}, debouncedSearch(300ms), setPage/PageSize/Search/Filter/clearFilters/setSort, hasActiveFilters}`; persisted in sessionStorage `list:<key>`; any change except page resets to page 1. Storage keys are versioned (e.g. `'yards:server'`).
- `useServerList<T>(list, cfg{queryName,url,sortKeys,filterParams,extra,refetchInterval,enabled})` → `{items,total,isLoading,isFetching,error,refetch,filterParams}`; sends `page/per_page/search/sort_by/sort_order` + mapped filters; ignores unknown sort keys; `buildFilterParams` exported. Backend opt-in paged envelope `data:{items,pagination}`.
- `useTripsList` — same for `/api/trips` but the paginator is Laravel-style (`data.data`, `data.total`); `TRIP_STATUS_OPTIONS`, `TRIP_SORT_KEYS`.
- `useSelection<T>(resetKey)` — id-keyed multi-page selection, `selectAllMatching(total)` mode (bulk by filter), `values` (row objects of ticked rows), reset when `resetKey` changes.
- `useBulkAction(kind, label)` + `bulkTargets(kind, action, selection, filterParams)` → posts `/api/{vehicles|drivers|yards|trips|geofences}/bulk-{deactivate|reactivate|delete|enable|disable}` with `{ids}` or `{filter}` (≤500), aggregates per-record results (`done`, `failures[]`), toasts, invalidates fleet caches. `bulkTargets` narrows filter-mode requests to rows the action can change.
- `useServerExport(path, noun)` → `{run(params), busy}` (CSV via `downloadServerCsv`). `useStatusCounts(kind, filterParams)` → `/api/{trips|vehicles|drivers}/counts` `{total, by_status}` (ignores status/paging/sort keys so chips don't zero each other).
- `useOptions(kind, params, {enabled, search})` → `/api/{vehicles|drivers|yards|geofences}/options` lean unpaged (≤1000, `meta.truncated`) for pickers (`components/OptionSelect` adds a search box when truncated).
- `useViewportList(name,url,params,enabled,maxPages=5)` — map layers by `bbox`, reads pages in parallel (≤500 records). `utils/mapViewport.ts`: `boundsToBbox`, `bboxToParam`, `parseBbox`, `pointInBbox` (clamped to ±180/±90; no antimeridian crossing).
- `useEditConflict(record, onReload)` — optimistic concurrency: `expected` (`{expected_updated_at}` to spread into PUT bodies), `handle(response)` (true on 409 → shows `ConflictBanner`), `banner`, `conflicted`. Quick actions use `utils/fleetConflict.ts` (`expectedUpdatedAt(record)`, `conflictMessage(response)`).

**Fleet settings / units / currency / options:** `useFleetSettings()` (`/api/fleet/settings`, staleTime 60 s → `{settings, isLoading, error, refetch}`; `todayIn(tz)`), `useUnits()` (from `settings.unit_system`, metric fallback), `utils/units.ts`
(`unitsFor`, `Units{distance,volume,economy,speed,length,weight,perDistance}` with `from/to/label/identity`, `toMetric`, `toDisplayString`, `formatQty`; identity for metric — never rounds), `utils/fleetCurrency.ts` (`useFleetCurrency()` = company currency from `/api/companies/:id`, module store `formatFleetMoney`),
`utils/fleetOptions.ts` (`useFleetOptions()` → value lists `fuel_types, ownership_types, employment_statuses, availability_statuses, vehicle_categories`; `optionLabel`), `hooks/useDetectedTimezone.ts` (`detectTimezone`, `isUtcLike`), `utils/datetime.ts` (`toIsoInstant` — datetime-local → ISO, `toDatetimeLocal`).

**Analytics data hooks** (see `domains/fleet-analytics-kit.md`): `useOverviewData`, `useAnalyticsData`, `useTripsReport`, `useFuelReport`, `useMaintenanceReport`, `useMaintenanceSchedules`, `useCompanyLogs`, `useComplianceReport`, `useFleetRealtime`.
All keep the `fleet-dashboard-*` prefix and use `placeholderData: keepPreviousData` + `refetchInterval` 300 000 ms.

**Misc:** `useKpiColumns` (analytics), `useSimpleQuery`; `usePaginatedQuery` is dead code.
