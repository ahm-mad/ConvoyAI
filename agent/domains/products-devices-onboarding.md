# Domain: Products, devices & onboarding (IoT connectivity)

Sidebar: **Connect** section → "Manage Products" (`hasPermission('all-product')`), "Products" (super admin `/all-products`), "Connector Health" (`all-connect`). A **Product** = a device model/type owned by a company; **Devices** = physical sensors with a globally-unique `device_unique_identifier` (DevEUI/serial). Only **HTTPS webhook** ingestion works end-to-end; MQTT is "Coming Soon".

## 2. Add product / device flow (`forms/MultiStepForm/AddDevices.tsx`, `@ts-nocheck`)

Modal, **two steps** ("Product & Devices" / "Network Protocol"), fixed size (`w-[860px] max-w-[95vw]`; height `h-[600px]` new-product flow, `h-[480px]` existing-product flow — deliberately no resize between steps/tabs). Removed by owner decision: the "Existing/New/Template" choice, product templates, "device protocol" concept (only network protocol exists), device Tags.

- Step 1: product name (`SecondstepForm`, only for a brand-new product) + devices: manual rows (`TagInput`: name, `device_unique_identifier`, location; "+ Add Another Device") and/or **CSV import** (`Dropzone` `.csv` ≤5 MB → `utils/csvDevices.ts` parse/validate ≤500 rows, columns `device_unique_identifier,name,location`, preview in `ThirdstepForm`). Save = `multipart/form-data` `POST /products` (product fields + `devices` JSON + optional CSV `file`; existing product → `existing_product_id`).
- **Retry/partial-failure logic** (important): `createdProductId` is captured from any response containing `product.id`; subsequent saves in the same modal send `existing_product_id` (never `product_name` again → no orphan products). After any save with failures `pruneToUncreatedDevices` removes the devices that were created (by identifier) and converts failed CSV rows to editable manual rows, so re-saving can never resend created devices (backend `device_unique_identifier` is globally unique). `DeviceErrorTable` banner + "Continue with N created" only when something was created. Always check `import_summary.created_count`, not just `success`.
- Step 2 (`FourthstepForm` + `HTTPProtocol`): loads `GET /protocols` (HTTPS first), `POST /get-encrypt-token {protocol_id, product_id}` → ingestion token (header `token` for `POST /api/webhook`); shows webhook URL (**hardcoded** `https://api.example.com/api/webhook` — known finding) and copy button; Acknowledge disabled on the MQTT tab; step-3 "Don't Skip" lock has no close button (deferred by owner). Back button deliberately removed after the save step.
- The "first packet" arrives → socket `packet:initial` → `GlobalPacketListener` shows a persistent toast "📦 Packet received for: X — Click here to configure" → `/products/:id/configuration`.

## 3. Attribute configuration (`AttributeModal.tsx` 663 L, `@ts-nocheck`)

Modal for one attribute: label, unit (options), alert conditions (react-hook-form `useFieldArray`, If/And/Or + comparator + value). Saves `POST /attribute/preference/setting/store` (creating; `PUT …/setting/:id` edits) with a fixed default `widget_type` (`DEFAULT_WIDGET_TYPE` = first entry of `widgetsIconMapper` because the widget-type picker was removed). "Remove configuration" → `DELETE /attribute/preference/setting/:id` which **cascades to a linked Rule Builder rule** — inline confirmation states this. Width `w-[620px] max-w-[95vw]`.
`CreateProductFromPayload.tsx` (503 L): prototype flow (select a real packet from history → rename product → mapping preview → save attribute settings) wired to 4 existing endpoints; check usage before relying on it.

## 4. Packet history (`ManageDevice` history tab, flow 02)

Device-filter dropdown (all devices under the product; per_page ≤100 backend cap), one column per configured attribute (from `/product-settings/:id`), collapsible "View Details" JSON viewer (`PacketPayloadViewer`, per-node open state; `RadixTable` `isRowExpanded/renderExpandedRow` opt-in props), live refetch via socket `device:value` scoped by `productId` (and by selected device). `GET /dashboard/packet-history`.

## 5. Backend notes that shaped the UI

- `GET /products` pagination is offset-style (`page` served = `floor(page/per_page)+1`; fixed in D-0146 to be 1-based-compatible); `GET /products/:id` device list search matches name, DevEUI and location; deterministic `id` tie-breaker added (D-0147).
- `last_updated` on devices is a pre-formatted string ("19 hours ago" / "never") — render as-is (don't `new Date()`).
- Device online status: Home page uses `latest_packet` recency (backend computes; hints under the numbers: "Reporting right now" / "Not reporting right now" / "Reported within 24h — may include offline devices").
- ProtocolIntegration (`/mqtt-configurations`) exists but MQTT is not active; `components/MQTTProtocol.tsx` (591 L) is parked.
