# Design system & UI conventions

## 1. Tokens (`src/index.css` — THE token file)

Dark is the default (NOC/industrial console look); `.light` on `<html>` overrides everything. Use Tailwind utilities generated from the `@theme` block or `var(--color-*)`; never hardcode hex in components.

Cards = `bg-surface-1`, inputs/chips = `bg-surface-2`, hover/skeleton = `surface-3`                                                                                                         |
| Lines          | `line` #22282e, `line-soft` #181c20 (`border-line`, `border-line-soft`)                                                                                                                                                                                                                 |

Facts: **all scrollbars are hidden globally** (`*{scrollbar-width:none !important}` + webkit). Number-input spinners hidden. Typography is arbitrary-size heavy: `text-[11px]`, `text-[10px] uppercase tracking-wider text-ink-2` for section labels — match it.
The guest marketing site uses the same tokens plus arbitrary colours (`bg-[#0F1D2A]`); `GuestHomeComponents/index.css` (own Inter/JetBrains token set) is dead — never imported.
`styles/global.css` is only Calendly overlay fixes + `.bg-grid`/`.text-gradient-cyan` for GuestHome.

## 2. Component libraries coexist (established, not accidental)

Tailwind utility classes everywhere + **Radix** primitives (select, checkbox, label, popover; `dropdown-menu`/`switch` are imported but only available transitively via `@radix-ui/themes`, which itself is never imported) + **MUI** only where behaviour is needed (global `Modal` = MUI `Dialog`; `Switch`/`Checkbox`/`Modal`/`TextField`
in a handful of forms; MUI `DatePicker` in `AccountSettings`; MUI SVG icons in `assets/icons/MUIicons/*`) + **antd** `Tree` (Assets only, themed via `ConfigProvider` with the cyan token) + **lucide-react** icons (dominant) + react-icons + custom SVG icons (`assets/icons/ReactIcon/*`, dynamic `IconWrapper`).
Unused deps (details in `architecture/dependency-map.md` §3b): `zustand`, `dayjs`, `date-fns`, framer-motion/motion, vaul (the code uses `Intl`/native `Date`; fleet date maths in `analytics/format.ts`). Don't "clean up" library mixes without being asked; the planned unification is the deferred global UI pass (§7).

## 4. Patterns to follow

- **Forms**: legacy/complex forms = react-hook-form + yup (`src/validation/*`); new Fleet forms = plain `useState` per field with inline required checks, shared field components (`VehicleFields`, `DriverFields`, `RecordForm` schema-driven). Match the pattern of the file you edit; don't unify unprompted.
- **Field payload rules for PUT (fleet)**: send only changed fields, `null` clears a nullable field, always include `expected_updated_at` (optimistic concurrency).
- **Never window.confirm/alert** — inline two-step confirms and toasts. Business-rule 422 messages from the backend are shown **verbatim**.
- **No fabricated numbers**: show "—" / "not enough data" instead of a plausible placeholder; never `Math.random()` for real-looking metrics.
- **Every table/chart**: loading skeleton → empty state with next step → error + retry → keep previous data dimmed while refetching (`keepPreviousData`).
- **Charts**: chart.js (registered in `analytics/chartSetup.ts`), colors only from `useVizColors()`; no dual axes; donut ≤6 slices; every chart has a table twin (WidgetCard toggle); lines straight between daily points; whole-number axes for counts.
- Leaflet maps: MapTiler tiles (`NEXT_PUBLIC_MAPTILER_KEY`), light/dark tile styles via `useTheme().isLight`; marker components `VehicleMarker` (SVG pin colored by position freshness), `YardMarker`.
- Fixed-size modals + `overflow-y-auto` inside; PageScroller pattern (own scroll container sized `window.innerHeight - top`) for pages under the fleet nav so sidebar/navbar stay put.

## 5. i18n

`src/i18n.ts`: i18next + HttpBackend (`/locales/{lng}/{lng}.json`), LanguageDetector (localStorage then navigator), `fallbackLng:'en'`, `supportedLngs:['en','ar']`, `debug:true`, `keySeparator:'.'`.
en ≈ 921 keys, ar ≈ 915. **Only ~71 files use `useTranslation`** (sidebar, navbar, forms, product/rules/asset screens, widget forms). **All Fleet screens and the analytics area are English-only hard-coded strings** (a possible future task; foreign clients rule applies to units/tz/currency, not yet language).
Arabic RTL: only a couple of `rtl:` utility classes exist; there is no global `dir` switch — RTL is not really implemented.

## 6. Accessibility state

Analytics pages passed an axe-core run (Fuel, Service history; other pages partially): `role="presentation"` on chart canvases inside labelled wrappers; KPI tiles = card + overlay button (no nested buttons); `.a11y-muted`; focus-visible outlines (`outline-accent-cyan`) on Fleet controls; ARIA on toggles/radiogroups (`ViewSwitch`), `aria-current` on nav links.
The legacy app (widgets, old lists) has not had an a11y pass. Screen-reader listening test never done.
