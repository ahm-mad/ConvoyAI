## Conventions (API_CONTRACT §2)

- Base `${NEXT_PUBLIC_API_URL}api/…`; `Authorization: Bearer <JWT>` (7 days, embeds roles+permissions; 401 `{"success":false,"message":"Authentication required"}`; 403 `Requires role/permission: X`; other company's records → 404).
- Envelope: success `{success:true, message?, …payload}`; error `{success:false, message, errors?{field:[msgs]}}` (`errors` on 422). **422 = validation AND most business-rule failures** (Laravel-sentence messages — show verbatim). 409 = optimistic-concurrency conflict `{success:false, message, current:{id,updated_at,updated_by,updated_by_user}}`.
- A few endpoints answer HTTP 200 with `success:false` ("no results"); one 404 carries `success:true` (`GET /attribute/preference/setting/{id}`) — don't branch on status alone.
- Ids are integers (some asset endpoints string ids); in socket payloads ids are **strings**. Timestamps: ISO with `Z` and Laravel `Y-m-d H:i:s` coexist (per field).
- Pagination styles: Laravel paginator (`current_page,data,…,total`), app style `{items, pagination{page,per_page,total,total_pages}}`, and offset-ish `page` on `GET /products`. Fleet lists are opt-in paged: `page`/`per_page` present → `data:{items,pagination}`, absent → flat array (except always-paged: sub-lists, `GET /incidents`, `GET /maintenance-schedules`, `GET /fleet/attention`, company logs).
- Fleet list conventions: `search`, `sort_by`/`sort_order` (NULLs last), filters, id lists as `a,b` or `a[]=`; `…/export` streams CSV (UTF-8 BOM, ≤50,000 rows, else 422); bulk actions by `ids` or `filter` (≤500, per-record `{id,ok,changed,label,message}`); audit fields `created_by/updated_by(+_user)`.
- Uploads are `multipart/form-data` (`image`, `profile_image`; ≤10 MB, profile ≤3 MB; stored in Cloudflare R2, public URLs). JSON body limit 100 KB (malformed/oversized → 500). No rate limiting. Unknown route → Express HTML 404.
- Health: `GET /health`, `GET /ready` (outside `/api`).
- Auth flows: register → verify e-mail (`{FRONTEND_URL}/verify-token/{token}`) → login (`companyInfo` decides onboarding); Google popup flow posts `GOOGLE_AUTH_SUCCESS` via `postMessage`; password reset = forgot → verify-reset-token → reset.

## Known gaps: frontend calls that the backend does NOT serve (as of that snapshot — re-verify before relying)

- `DELETE /api/account/delete` (Account Settings "delete account") — not implemented → button fails. `POST /api/companies/create-with-user` (`AddCompanyForm`) — not implemented. `POST /api/companies/bulk/destroy` (`SuperAdminDashboard`) — wrong path, real one is `POST /companies/bulk-delete`.
- `POST /api/add-demo-product`, `GET /api/check-configured-devices`, `POST /api/simulate-packet` exist only in the MSW fake backend (demo).
- `POST /api/highlight-attributes` AI endpoint needs an AI key (404/502 in some envs). MQTT ingestion not implemented (`/mqtt-configurations` CRUD exists). Payments (Stripe) deferred.
- Hard-coded webhook URL `https://api.example.com/api/webhook` in `HTTPProtocol.tsx` (should be derived from env).
